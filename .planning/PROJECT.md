# Project: Telegram AI Repost & Publishing Pipeline Bot

## Executive Summary
Бот для Telegram-канала на базе Python и aiogram 3, реализующий асинхронный конвейер:
**«Получить → Переписать → Сгенерировать картинку → Утвердить / Опубликовать»**.
Бот предназначен для личного использования автором канала. Архитектура обеспечивает полную отказоустойчивость, защиту от дубликатов, сменные адаптеры LLM и генераторов изображений, а также обязательный этап ручной верификации (approval gate) перед публикацией в целевой канал.

## Core Requirements & Value Proposition
1. **Приём контента:**
   - Поддержка ссылок на статьи (автоматический парсинг через Trafilatura / BeautifulSoup).
   - Поддержка произвольного сырого текста.
   - Опциональное управление тоном пересказа (`/rewrite formal`, `/rewrite casual`, `/rewrite dynamic`, и т.д.).
2. **Антидубликация (Content Dedup):**
   - Расчет хэша URL / содержимого статьи, хранение истории в базе данных (SQLite).
   - Оповещение пользователя, если материал уже обрабатывался.
3. **Рерайт контента (LLM Layer):**
   - Модульная архитектура провайдеров LLM (DeepSeek Chat/V3, OpenAI GPT-4o-mini, Anthropic Claude).
   - Надежный системный промпт с сохранением ключевых фактов, метрик, цифр, очисткой от рекламы и генерацией 3–5 хэштегов.
   - Механизм fallback при сбое основного провайдера.
4. **Генерация визуалов (Image Generator):**
   - Автоматический синтез промпта обложки на основе статьи с учетом заданного стиля.
   - Поддержка провайдеров (DALL-E 3, Flux API, мок/заглушка).
   - Graceful degradation: возможность утвердить и опубликовать без картинки при сбое генератора.
5. **Human-in-the-loop (Approval Gate):**
   - Отправка предпросмотра поста с инлайн-кнопками: «Опубликовать», «Перегенерировать картинку», «Переписать текст», «Отклонить».
   - Защита канала от галлюцинаций нейросети.
6. **Надежность и персистентность:**
   - SQLite с асинхронным доступом (`aiosqlite`).
   - Очередь задач с отслеживанием состояний (`PENDING`, `EXTRACTING`, `REWRITING`, `GENERATING_IMAGE`, `AWAITING_APPROVAL`, `PUBLISHED`, `FAILED`).

## Architecture Standards
- Domain-Driven Design (DDD) с четкими границами контекстов.
- System Design Document (SDD) согласно `SDD-TEMPLATE.md`.
- Архитектурные решения зафиксированы в ADR (`docs/adr/`).
- 100% покрытие бизнес-сценариев тестами (Unit, Integration, E2E) по циклу TDD.
