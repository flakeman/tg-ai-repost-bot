# ADR-001: Event-Driven Asynchronous Pipeline Architecture

## Status
Accepted

## Context
Владельцу канала требуется автоматизировать пересказ новостей и статей по схеме «Получить → Извлечь → Переписать → Сгенерировать обложку → Утвердить → Опубликовать». Выполнение всех шагов синхронно в одном Telegram-обработчике сообщений блокирует бота, приводит к тайм-аутам (генерация картинок и рерайт могут занимать до 15-30 секунд) и делает систему хрупкой.

## Decision
Мы выбираем асинхронный событийно-ориентированный конвейер (Pipeline State Machine):
1. Telegram Bot быстро принимает запрос, валидирует его, создает задачу со статусом `PENDING`, регистрирует хэш и возвращает пользователю мгновенный ответ.
2. Конвейер выполняет каждый шаг изолированно (`EXTRACTING` -> `REWRITING` -> `GENERATING_IMAGE` -> `AWAITING_APPROVAL`).
3. Состояние каждого шага персистится в базе данных, позволяя возобновить работу или отобразить точный этап сбоя.

## Consequences
- **Плюсы:** Высокая отзывчивость бота, отсутствие блокировок event loop, прозрачность статусов для пользователя, возможность перезапустить отдельный шаг (например, только перерисовать картинку).
- **Минусы:** Необходимость хранения промежуточных состояний и сериализации данных.
