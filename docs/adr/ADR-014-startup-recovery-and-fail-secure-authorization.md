# ADR-014: Восстановление незавершённых задач при старте и безопасная авторизация (Fail-Secure)

## Статус
Принято (Accepted)

## Контекст
1. При непредвиденных перезапусках сервиса (OOM, рестарт хоста, деплой новой версии) задачи, находившиеся в фазе исполнения (`EXTRACTING`, `REWRITING`, `GENERATING_IMAGE`), оставались в базе данных в «подвешенном» состоянии навсегда. Пользователь не получал ни черновика, ни сообщения об ошибке.
2. В функции `is_authorized` при отсутствии заполненной переменной `ADMIN_IDS` доступ по умолчанию был разрешён всем (`return True`). Если администратор случайно забыл указать ID, любой пользователь Telegram мог давать боту команды и тратить платный API-баланс.

## Решение
1. **Startup Recovery Daemon:**
   - При старте `src/main.py` после инициализации БД запускается процедура `recover_orphaned_jobs()`:
     - Запрашиваются все задачи со статусом `IN_PROGRESS` (`EXTRACTING`, `REWRITING`, `GENERATING_IMAGE`).
     - Задачи либо автоматически повторно ставятся в очередь воркера на доработку (если с момента создания прошло менее 1 часа), либо маркируются `FAILED` с понятным описанием причины (`Процесс был прерван перезапуском сервера`).
     - Автору отправляется сервисное уведомление в Telegram о статусе его задачи.
2. **Fail-Secure авторизация:**
   - Метод `is_authorized` переводится в режим строгой безопасности:
     ```python
     def is_authorized(user_id: int, settings: Settings) -> bool:
         if not settings.admin_ids:
             logger.warning("ADMIN_IDS is not configured! Denying access to user %s", user_id)
             return False
         return user_id in settings.admin_ids
     ```
   - Добавлен лог-алерт при запуске бота, если список администраторов не задан.

## Последствия
- Положительные:
  - Исключение потери контента и "забытых" задач при сбоях сервера.
  - Защита платных API от несанкционированного доступа случайных пользователей.
