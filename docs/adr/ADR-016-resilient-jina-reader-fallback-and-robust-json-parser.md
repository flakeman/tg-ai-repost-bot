# ADR-016: Резервный экстрактор контента Jina Reader и устойчивый парсер JSON

## Статус
Принято (Accepted)

## Контекст
1. **Проблема 403 / Cloudflare:** При попытке парсинга некоторых новостных сайтов и блогов (защита от ботов, Cloudflare, Paywall) прямой HTTP-клиент `httpx` получает ошибку `403 Forbidden` или капчу.
2. **Проблема сбоев парсинга JSON:** Модели LLM иногда возвращают ответ в формате JSON, но с мелкими синтаксическими отклонениями (неэкранированные кавычки в цитатах, `trailing commas`, лишний текст до/после JSON блока). Стандартный `json.loads` в Python в таких случаях выбрасывает `json.JSONDecodeError`, приводя к сбою всей задачи.

## Решение
1. **Каскадный экстрактор контента (`TrafilaturaExtractor`):**
   - Уровень 1: Прямой запрос через `httpx` с имитацией современных браузерных заголовков.
   - Уровень 2: Извлечение через `trafilatura` с лимитом размера HTML (1.5 МБ).
   - Уровень 3: Если прямой запрос возвращает 403 / 503 или `trafilatura` не находит текста — переключение на резервный прокси-экстрактор **Jina Reader API** (`https://r.jina.ai/<target_url>`), возвращающий чистый Markdown без выполнения клиентского JS.
2. **Устойчивый парсер JSON (`RobustJsonParser`):**
   - Алгоритм многоуровневого парсинга:
     1. Очистка Markdown code blocks (```json ... ```).
     2. Попытка стандартного `json.loads`.
     3. При ошибке: нормализация trailing commas (запятых перед `}` и `]`) и экранирование невалидных символов.
     4. Regex-экстракция целевых полей (`title`, `body`, `hashtags`, `image_prompt`, `image_prompts`), если JSON всё ещё некорректен.

## Последствия
- Положительные:
  - Успешное извлечение статей даже с защищённых и сложных сайтов.
  - Повышение надёжности работы рерайтера до 99.9%, исключение сбоев из-за синтаксиса LLM.
