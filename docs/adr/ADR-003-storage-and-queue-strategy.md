# ADR-003: Storage and Deduplication Strategy (Async SQLite with WAL)

## Status
Accepted

## Context
Бот предназначен для личного использования одним владельцем канала (или небольшой группы администраторов) на VPS-сервере. Развертывание тяжелых СУБД (PostgreSQL) или отдельных брокеров (Redis/RabbitMQ) увеличивает потребление памяти и усложняет эксплуатацию. При этом критически важны:
1. Защита от повторной обработки уже опубликованных или обработанных статей (дедупликация по хэшу).
2. Сохранение истории и состояния задач.
3. Отсутствие блокировок при одновременной записи.

## Decision
Мы используем встроенную базу данных SQLite с асинхронным драйвером `aiosqlite` и включенным режимом WAL (Write-Ahead Logging):
1. Хранение `content_hash` с уникальным индексом `idx_jobs_hash`.
2. Режим `PRAGMA journal_mode=WAL;` и `PRAGMA busy_timeout=5000;` обеспечивают высокую параллельность чтения и записи без конфликтов.
3. Очередь задач управляется через статусы в БД и асинхронный воркер `asyncio.Queue` в памяти приложения с восстановлением незавершенных задач из БД при старте.

## Consequences
- **Плюсы:** Нулевые накладные расходы на внешние сервисы, простота резервного копирования (один `.db` файл), надежная дедупликация.
- **Минусы:** Не подходит для горизонтального масштабирования на несколько серверов (для личного бота это не требуется).
