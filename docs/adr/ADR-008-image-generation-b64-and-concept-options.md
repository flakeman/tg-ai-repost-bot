# ADR-008: Real AI Image Generation via Base64/FSInputFile and Multi-Concept Prompt Suggestions

## Status
Accepted

## Context
1. Некоторые генераторы изображений (включая шлюзы OpenAI, отдающие модель `gpt-image-2`) возвращают данные изображения в поле `b64_json` (Base64), а не публичный URL `item.url`. Попытка прочитать `item.url` приводила к `None` и срабатыванию плейсхолдера.
2. В превью выводилось техническое сообщение `(Изображение отсутствует или используется плейсхолдер)`, что ухудшало пользовательский опыт. Пользователю требовалось видеть 3–4 альтернативные идеи/промпта для обложки в разных стилях.

## Decision
1. В `DalleImageGenerator` поддержать декодирование `b64_json`: если URL отсутствует, декодировать байты Base64 и сохранять изображение локально в каталог `storage/images/gen_<uuid>.png`.
2. В `send_draft_preview` (`handlers.py`) и `TelegramPublisher` (`publisher.py`) реализовать функцию `get_photo_target(image_url: str)`: если строка начинается с `http`, отправлять URL, если это локальный путь — оборачивать в `FSInputFile(image_url)`.
3. В системном промпте LLM (`prompts.py`) обязать модель возвращать массив `image_prompts` из 4 разнообразных концептов (3D-рендер, инфографика/вектор, фотореализм, неон/киберпанк) с описанием визуальной сцены на русском языке.
4. Выводить сформированные варианты `image_prompts` в сообщении предпросмотра редактору под блоком `🎨 Варианты генерации обложки:`.
5. Полностью убрать упоминания плейсхолдеров из пользовательского интерфейса.

## Consequences
- **Плюсы:** Поддержка всех типов ответов API генерации картинок (URL и Base64), надежная доставка медиа в Telegram через локальные файлы, креативный выбор для редактора.
- **Минусы:** Необходимость периодической очистки каталога `storage/images/` от старых файлов генерации.
