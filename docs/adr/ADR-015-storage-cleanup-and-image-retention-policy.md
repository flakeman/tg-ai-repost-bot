# ADR-015: Политика хранения и ротации сгенерированных изображений (TTL Cleanup)

## Статус
Принято (Accepted)

## Контекст
1. Генератор изображений сохраняет каждый файл на диск в директорию `storage/images/gen_*.png`.
2. В процессе работы (регенерация обложек, отклонённые варианты, регулярные публикации) накапливаются сотни мегабайт картинок.
3. Отсутствие механизма очистки приводит к постепенному заполнению диска VPS, что чревато сбоями SQLite и остановкой операционной системы.

## Решение
1. **Регламент хранения (Retention Policy):**
   - Установить TTL (время жизни) для локальных файлов обложек в 14 дней.
   - Опубликованные в канал посты сохраняются на серверах Telegram и не зависят от локального диска бота после отправки.
2. **Модуль автоматической очистки `ImageStorageManager`:**
   - Функция `cleanup_expired_images(images_dir: str, max_age_days: int = 14) -> int`:
     - Сканирует файлы `gen_*.png` в `storage/images/`.
     - Проверяет время изменения файла (`os.path.getmtime`).
     - Удаляет файлы, возраст которых превышает заданный TTL.
   - Запускается:
     1. Один раз при старте бота.
     2. Фоновой периодической корутиной (раз в 24 часа).
     3. По вызову из команды `/settings` (ручная очистка кэша).

## Последствия
- Положительные:
  - Размер каталога `storage/images/` стабилизирован и не превышает разумных пределов (обычно < 100 МБ).
  - Безопасная работа на серверах с небольшим объёмом диска.
