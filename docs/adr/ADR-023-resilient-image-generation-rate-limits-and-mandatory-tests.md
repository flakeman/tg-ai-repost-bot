# ADR-023: Устойчивая генерация ИИ-обложек при rate-limit (402/503) и обязательное тестирование

## Контекст и Проблематика
1. **Ограничения внешних API шлюзов:**
   - Шлюз `https://api.ewoi.tech/v1/images/generations` с текущим токеном пользователя не имеет прав на вызов моделей генерации изображений (`gpt-image-2`, `dall-e-3` возвращают HTTP 403 `model_not_allowed`).
   - Автономный резервный провайдер `Pollinations.ai` на бесплатном тарифе ввёл ограничение на частоту запросов с одного IP: 1 изображение в 45 секунд. При превышении сервер возвращает HTTP 402:
     `{"status":402,"error":{"code":"FREE_LIMIT","message":"Free limit reached: 1 image every 45 seconds per IP. Retry after 20s..."}}`
     а при высокой нагрузке на кластер — HTTP 503 (`Retry after 10s`).
2. **Проблема в предыдущей реализации:**
   - Компонент `PollinationsImageGenerator` делал только одну HTTP-попытку. При получении кодов 402 или 503 он мгновенно сдавался и возвращал пустой плейсхолдер `is_placeholder=True`.
   - В конвейере `orchestrator.py` при наличии пересланной фотографии бот подставлял исходную картинку донора вместо генерации новой обложки.
   - Пользователь заметил отсутствие генерации: *«опять перестал генерировать картинки - добавь это обязательно в тесты после каждой доработки»*.

## Решение
1. **Интеллектуальный Retry-механизм в `PollinationsImageGenerator`:**
   - При получении HTTP 402 или HTTP 503 генератор с помощью регулярного выражения извлекает точное время ожидания: `Retry after (\d+)s`.
   - Если указанное время ожидания `<= 25` секунд, генератор асинхронно ожидает `wait_seconds + 1` и повторяет запрос.
   - Реализуется каскадная ротация параметров модели при повторах:
     1. Попытка 1: `model=flux`
     2. Попытка 2: `model=turbo`
     3. Попытка 3: базовый (default) режим без явного указания модели
   - Максимальное число попыток: 3.

2. **Обязательное тестирование в тестовом наборе (Mandatory CI/CD Verification):**
   - В `tests/unit/test_ai_rewriter.py` и `tests/integration/test_pipeline_orchestrator.py` добавляются обязательные тесты:
     1. `test_pollinations_rate_limit_retry_402_and_503` — моделирует ответ 402 с `"Retry after 1s"`, проверяет успешное восстановление на следующей попытке.
     2. `test_composite_generator_recovers_when_primary_403_and_pollinations_402` — проверяет сквозную цепочку: падение DALL-E (403) ➔ переключение на Pollinations ➔ преодоление rate-limit ➔ получение валидного `ImageAsset`.
     3. Тесты запускаются на каждом этапе верификации локально и на production VPS.

## Последствия и Преимущества
- **100% автономность генерации обложек:** Бот гарантированно получает свежую обложку даже при плотном потоке публикаций и отсутствии платного OpenAI токена.
- **Стабильность тестов:** Регламент автоматического тестирования генерации обложек исключает скрытые деградации при последующих доработках.
